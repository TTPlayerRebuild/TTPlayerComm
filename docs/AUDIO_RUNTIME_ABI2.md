# 高精度 PCM 音频服务 ABI 2

更新日期：2026-10-20。

本接口供重建宿主显式选择高精度处理。它不改变原版均衡器／环绕、原运行 ABI 1，也不改变 Winamp 插件宿主的行为。原版 EXE 不主动调用本接口，因此仅替换 DLL 不会自动升级原版播放器的整条输出链。

## 1. 查询和兼容

- 头文件：`sdk/include/ttpcomm/audio_api.h`、`audio_client.h`。
- 继续使用 ordinal 501 / `ttpcomm_query_runtime`，传入 `version=2`；不新增导出。
- 静态发行校验使用中性语言 RCDATA 504，16 字节四个小端 DWORD：`0x41415054, 1, 2, 3`，依次表示 TPAA 标识、描述符版本、音频 ABI、编码器＋效果能力。构建／下载校验可读取资源，不必执行 DLL；运行时仍须实际查询并验证函数表。
- 新函数表 `TtpCommAudioApi` 在 x86 下为 56 字节，旧 `TtpCommRuntimeApi` 仍为 80 字节。
- 原 67 个导出、4 个扩展入口共 71 个保持不变。原版 ordinal 103／104 的源实现不变。
- 调用者清零表并填写 `size`；查询失败不接受部分能力。`ttpcomm::host::QueryAudio(HMODULE, api)` 同时检查版本、完整函数指针和异常返回。
- 不加载未经指定的 DLL；宿主持有模块引用，直至对象和函数指针均不再使用。
- 固定宽度类型、`__cdecl`、`#pragma pack(8)`；不得跨边界传递 STL 或 CRT 所有权。
- 不同对象可并行使用，同一个对象的 configure/process/reset/destroy 由调用者串行。
- 保持 VC-LTL／YY-Thunks、x86 IA32 基线；没有引入新的第三方依赖。

## 2. 最终输出编码器

输入为交错 `double` 半幅样本：内部 ±0.5 对应标准外部浮点 ±1.0。调用者必须在最后量化前完成需保留精度的处理。

| 项目 | 行为 |
|---|---|
| 整数容器 | PCM8（无符号）、PCM16／24／32（有符号），小端 |
| 有效位 | 1 至容器位数；低位补零，24-in-32 左对齐 |
| 浮点容器 | IEEE float32／float64，有效位必须等于容器位宽 |
| 增益 | 不传数组为 unity；否则每声道一个有限增益，在量化前应用 |
| 整数舍入 | 最近偶数舍入，饱和到最终有效位范围 |
| 浮点输出 | 半幅乘二，保留负零和可表示的超满幅值；超过浮点类型可表示范围时饱和并计数 |
| 非有限值 | 输入或增益相乘结果为 NaN／Inf 时输出静音并计数；非有限增益参数直接拒绝 |
| 抖动 | `0` 关闭；`1` 为不整形的 TPDF，峰峰值 2 个最终有效位 LSB；浮点输出不加抖动 |
| 可复现性 | 实例独立 PRNG，固定 seed；reset 重置序列；改变调用分块不改变序列 |
| 格式限制 | 1–256 声道，采样率 1–768000 Hz，block_align 必须等于声道数乘容器字节数 |

`encoder_encode` 接受帧数和字节容量。返回本次编码字节数、削波样本数、非有限样本数。输入无效或容量不足时，不写输出，不前进随机状态。函数不分配堆内存；输出不得与输入或增益数组重叠。

原样输出应保留原始浮点字节流，不必绕经半幅域：IEEE float64 最小次正规数先除二可能下溢。这是内部幅度约定的表示边界，不能据“使用 double”就宣称所有浮点位模式均可往返恢复。

此处的 TPDF 不是原版噪声整形算法的替代实现。ABI 1 的历史量化器继续保持原语义；宿主必须明确选择处理策略。

## 3. 现代均衡器与环绕对象

### 均衡器

- 10 个频段边界为 32、64、125、250、500、1000、2000、4000、8000 Hz，另有前置增益。
- 每个频段和前置增益均接受 -60 至 +24 dB。
- 采用 float64 FIR／FFT；按 `511 / 44100` 秒目标时长缩放滤长，取奇数，限定 63–16383 taps。
- FFT 取不小于两倍滤长的二次幂；overlap-save 处理所有声道，不存在原版只处理前十声道的限制。
- 支持 1000–768000 Hz、1–32 声道。滤长受限的低采样率使用至少 63 taps。
- 新算法使用规范化 Kaiser 窗（β=8.6），不是原版私有窗函数的逐样本复制。
- 切换参数先完整创建新频域核；内存分配失败保留旧参数与历史。
- 两个核使用相同输入历史，按帧线性交叉渐变；`transition_frames=0` 表示显式立即切换，最大为 10 秒。
- 非有限输入置零；不会强制将正常浮点样本削波到 ±0.5。

**固定时长解决高采样率下滤波器越来越短的问题，不代表有限长度 FIR 能完整实现窄低频段的目标增益。**

真实新 DLL 正弦测试中，将 32–64 Hz 频段提升 6 dB，48 Hz 实测：

| 采样率 | 实测增益 |
|---|---:|
| 44.1 kHz | 1.834485 dB |
| 48 kHz | 1.835909 dB |
| 96 kHz | 1.835909 dB |
| 192 kHz | 1.835909 dB |
| 384 kHz | 1.836305 dB |

高采样率不再使响应继续显著变弱。若需 48 Hz 更接近 6 dB，须增加滤长／延迟或改用另一类均衡器；当前没有将这一点表述为完成。

### 环绕

- 按采样率分配实际 16 ms 延迟环，取最接近的整数帧，不再封顶 1024 样本。
- 对延迟的前两声道平均值做双精度一阶高通／低通，约 200–7000 Hz 的分量以反相方式加入前左右声道。
- 其他声道继续通过均衡器，但不参与环绕混合。
- 强度 1–16，混合增益为 `strength / 64`；强度／启停也按指定帧数过渡。
- 这是独立的现代环绕策略，不宣称与原版 Dolby 私有算法完全一致。

### 流式、延迟和结束

`effects_process` 分别报告实际消耗和产出帧数。输出容量可导致部分消耗；宿主只能重传未消耗部分。输入输出不得重叠，函数内不分配堆内存。

`END_INPUT` 只有在本次提供的输入全部消耗后生效。之后持续以空输入和 `END_INPUT` 调用，直到返回 `TTPCOMM_END`。

FIR 的中心延迟在对象内部补偿：跳过开头的群延迟样本，结尾以零补齐，**总输出帧数严格等于总接受输入帧数**。这会保留最终短块，不会把无限环绕衰减尾音额外延长到曲目长度之外。未提供 END 的对象不会猜测歌曲结束。

`effects_info` 返回 FIR taps、FFT 大小、处理块长、原始群延迟、最大缓冲帧数和环绕延迟。群延迟补偿不消除实时缓冲所需的等待，播放时钟仍应采用已经交付输出的实际帧数。

reset 清空 FIR 历史、待处理块、输出队列、环绕环和滤波状态；保留最新目标参数，立即用于下一首歌。不保留上一首的过渡和尾音。

## 4. 验证与界限

私有测试位于 `rebuild/tests/hires_pcm_20261020/runtime`，不在本仓库和 Actions 中。

本机 Windows 11 的真实 DLL 验证通过 355184 项检查：

- 随机 PCM8／16／24／32 及有效位数，经 ABI 1 解码再由新编码器编码后逐字节一致。
- 边界饱和、正负半 LSB 的偶数舍入、24-in-32、每声道增益。
- float32／float64 的负零、超满幅、非有限输入。
- TPDF 统计、分块一致、reset 重复性，以及容量失败不改变状态。
- 44.1–768 kHz、1／6／16 声道均衡器；分块一致、首尾帧数、短尾、非原地输入校验、reset 无串音。
- 44.1／96／192／384 kHz 的 16 ms 环绕，以及只修改前两声道。
- 参数逐帧交叉渐变、reset 保留最终目标参数。
- 48 Hz 响应跨采样率对比。

ABI 1 回归另行通过：PCM／增益、严格 zlib／raw／CRC、ID3／PIC／FLAC 图片及 1999 组畸形输入、四线程调用。该私有旧测试仅把“未知 ABI”测试值从 2 改为 `0xffffffff`，因为 2 现在是已定义的新表。
