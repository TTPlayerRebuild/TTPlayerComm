# 只读归档服务（更新至 2026-10-12）

## 分卷定位与有界缓存后续修正

当前完整归档能力掩码 `16383`，新增可选 ABI 3 卷定位／卷清单表，继续使用原有查询导出。ABI 1／2 结构和原 67＋4 个导出不变。RAR 通过 UnRAR 的 Unicode 换卷通知记录实际卷链，从非首卷打开则复用引擎首卷规则；ZIP／7z 数字卷和标准 ZIP 也可由调用方定位跨目录文件。回调在调用线程同步完成，生产者只保留解析后的路径和文件句柄。

整组身份包含各卷路径、文件 ID、大小、最后写入时间及 `ChangeTime`。Win7 曾在覆盖后续卷且保留修改时间时复用旧数据；现通过动态 `NtQueryInformationFile` 读取变更时间修正，并同步用于 TAR／gzip 目录和辅助缓存。查询不可用则停止相关跨次缓存命中，正常读取保留。

成员缓存最多三个槽：一个当前成员（保留原有大 CUE 镜像复用），另两个槽只保留已校验且各不超过 128 MiB 的历史成员；不留下无读者的旧生产者。尚未共享固实解码器字典，也未自动预取下一曲。宿主添加缺卷窗口和工作进程会话传递，RAR 密码指纹覆盖实际整组文件；归档继续只读。

最新验证、原版对照和未完成边界见播放器仓库 `rebuild/docs/ARCHIVE_VOLUME_RESOLUTION_AND_CACHE_20261012.md`；下面各节为历次实施记录。

## 辅助文件与 ZIP／7z 分卷更新

当前完整能力掩码为 `8191`，旧导出和 ABI 1／2 结构保持不变。新增标准 `.z01…zip` 的磁盘号／卷内偏移转换，以及 `.zip.001`、`.7z.001` 的可定位连续输入；可选择任一卷，组内文件身份共同参与缓存校验，缺卷明确失败，最多 4096 卷。SDK `archive_volumes.h` 供核心和宿主共用组识别、只读读取及身份；没有拼接整包落盘。

TAR／gzip 完整枚举后缓存有界目录索引，小文件缓存扩展为 CUE／LRC／TXT／图片。数据最多 16 MiB／128 份、目录元数据另限 16 MiB，并服从更小调用预算。校验失败或取消不发布缓存；音频当前任务不被辅助文件读取挤出。RAR 分卷仍禁用跨次缓存，因为实际卷由 UnRAR 自行发现。

重建宿主接通包内歌词搜索、版本化转义关联表、编辑保存只读提示、同目录外置封面及 CUE 封面继承。ZIP／7z 分卷记忆密码使用整组 MD5／SHA-256，实际解码再次验证候选密码。压缩包仍不写回。

Windows 11／XP／Win7：349 项新增分卷检查、826 项真实界面与导入检查，以及原 115／251／2239／163／271 项回归均通过；原版对照日志归一化后一致。751 份新样本和辅助文件按测试后回传哈希核对只读。完整依据、限制和交付见播放器仓库 `rebuild/docs/ARCHIVE_AUXILIARY_AND_MULTIVOLUME_20261012.md`。以下是历史实施记录，当前能力与限制以本节及该文档为准。

## 大包导入与额外解码更新

当前完整能力掩码为 `4095`，ABI 1／2 结构及原 67＋4 导出不变。新增静态 bzip2 1.0.8／Zstandard 1.5.7 解码，支持 7z 方法 `0x040202`／`0x04F71101`；检查帧／块声明、完整结果、字典和分配预算。旧 ZIP 密码依次尝试 UTF-8、系统 ANSI／OEM；密码头误通过而 CRC 失败时清除候选临时输出再重试。非 PAX 旧 TAR 名称可回退系统 ANSI，PAX UTF-8 规则不变。

TAR／gzip 完整枚举及容器校验成功后发布有界 CUE 缓存（最多 128 份、16 MiB，并服从更小预算），缓存身份含外层文件身份／大小／修改时间。失败／取消不发布，clear_cache 一并清理；它不缓存整个音频镜像。7z／RAR 固实前序和 gzip 尾部推进会更新流的活动时间，避免目标输出暂时不增长时误超时。

宿主导入已移到工作线程，显示阶段／计数／取消，取消保留原列表；并发同包密码框合并，首次输入不预先全盘哈希，勾选记忆或需要改名指纹匹配时再计算。CUE 读取和播放可继承音频内嵌封面，仍禁止包内写回。

同一 x86 DLL 在 Windows 11／XP／Win7 通过新核心 115 项、密码 251 项、真实导入／窗口 745 项、媒体库 16 项、既有格式 2239 项，以及 ABI 1／2 的 163／271 项。原版对照重新运行。完整实测、固定源码哈希及剩余差异见播放器仓库 `rebuild/docs/ARCHIVE_IMPORT_PROGRESS_AND_CODECS_20261012.md`。下方为历次记录；未完成的边界以该新文档为准。

## 密码及文件头识别更新

2026-10-12 后续更新：完整能力掩码现为 `2047`。支持传统 ZIP／WinZip AES、RAR 数据／文件名加密、7z 数据／文件名加密；加密成员完成 CRC／认证校验后才返回成功。7z 改为静态 LZMA SDK 26.04，固定源码哈希和许可证见 `licenses/LZMA-SDK-PUBLIC-DOMAIN.txt`。

强文件头签名优先于后缀，覆盖 ZIP／RAR／7z／TAR／gzip。TAR 必须校验首块。读取、错误、取消、限制、只读和旧 ABI 约定保留；加密成员缓存还比较密码，不能绕过密码校验。

重建播放器接通密码输入、DPAPI 记忆和路径绑定的信息助手数据包；按文件名或 MD5+SHA-256 组合指纹选择候选并实际验证。错误后缀复用现有选项，在播放时提示改名，更新包内曲目逻辑路径。

Windows 11／XP／Win7：241 项密码与签名检查、725 项生产导入与交互、16 项媒体库改名竞争检查，以及原有 2236 项格式回归、163／271 项 ABI 回归通过。详细边界见播放器仓库 `rebuild/docs/ARCHIVE_PASSWORD_AND_SIGNATURE_20261012.md`。只替换原版播放器的 ttpcomm.dll 不会改变其 EXE 内的归档工厂。

以下各节为此前的分阶段记录；密码界面及加密支持的旧限制已由本节更新。多卷 ZIP／7z、未启用的压缩方法、TAR 稀疏映射和归档写回仍未加入。

## 格式扩展及只读确认（本轮早期记录）

ABI 2 现增加 TAR、gzip、tar.gz／tgz、7z、UTF-8 ZIP 和单卷 ZIP64，完整能力掩码 `511`。旧 67 导出、4 个扩展导出和函数表布局不变。新能力只供主动调用 ABI 2 的宿主使用；替换原版公共 DLL 不会改变原 EXE 的归档工厂。

## 当前实现：ABI 2

音乐 ZIP 与 RAR 现在共用后台成员存储。新增 `ttpcomm_query_archive_stream`（序号 503）；也可通过 `ttpcomm_query_archive` 查询 ABI 2。原 67 个导出、ABI 1 同步验证后返回的约定保持兼容。下方 2026-10-11 记录保留作为 ABI 1 的历史说明。

| 接口 | ABI 2 约定 |
| --- | --- |
| `enumerate` | ZIP／RAR 按成员顺序枚举；返回名称仅在回调期间有效 |
| `open_member` | 成员头就绪即可返回；后台解压，Read 等待需要的范围，Seek 调整独立游标 |
| `status` | 查询已产生字节、总长度、任务 ID、是否完成及最终 HRESULT；校验完成前为 E_PENDING |
| `clear_cache` | 释放当前缓存；有活跃读取者的任务仍然有效；卸载 DLL 前释放所有流并调用此接口 |

仅保留一个当前成员任务。键包括外层路径、文件身份、大小、修改时间、成员名和限制；Clone 独立游标。CUE 文本由宿主以不保留模式读取，不挤掉同源音频。普通释放当前任务可继续完成；最后一个已取消／超时的读取者退出时取消生产任务。生产线程不调用读取者的取消回调，回调只在调用者线程轮询，状态须保持到流及其 Clone 全部释放。

分卷组通过 ROADF_VOLUME 标识禁用跨次缓存，包括未跨卷的单个成员，避免只验证首卷而忽略其他卷变化。当前成员缓存不等于固实块缓存；切换不同固实成员仍可能重解前置数据。

ZIP 读取不再复用播放器的 SkinPackage：宽字符名称查找、文件目录索引、16 KiB 分块 Stored／Deflate、成员边界、结束标记、长度及 CRC 校验。支持 ZIP 注释和数据描述符；最新格式扩展还加入 ZIP64 和 UTF-8 标志，未加入加密 ZIP。皮肤包原有一次性读取语义不变。

Read 到最终长度时等待校验；后台错误不能变成成功 EOF。小成员内存、大成员自动删除临时文件沿用 ABI 1 的资源限制；播放器 CUE 文本预设更小上限。新的播放器启动及 Actions 校验要求 503 和 ABI 2，部署顺序为先发布新 DLL、再构建播放器。

### 状态接口与包装器生命周期（2026-10-12 验收补充）

SDK 公开 `IID_TtpCommArchiveStreamStatus` 和 `TtpCommArchiveStreamStatusInterface`，使用原有 ABI 2 GUID、单个 `Snapshot` 方法及调用约定；没有新增导出、改变函数表或提高 ABI 版本。状态服务通过 QueryInterface 查询该接口。

包装 IStream 的宿主必须让状态接口与外层流共享控制 IUnknown 和引用计数，不得直接转发 QueryInterface 返回内层对象。否则保留状态接口、先释放外层流时，外层持有的取消上下文可能提前销毁。本次播放器包装器已修复，并验证状态接口保留、重新查询 IStream、Clone 及最后释放的完整顺序。卸载 DLL 仍须先释放所有接口，再 clear_cache。

独立打包脚本已将导出数量校验更新为 67 个旧导出＋4 个扩展，共 71 个，保留哈希及 XP／Win7 导入核对。

## 2026-10-11：ABI 1 初始实施记录

## 实现范围

RAR 引擎已静态并入重建的 `ttpcomm.dll`，播放器不再通过 Windows Shell 解压 RAR，也不要求安装 WinRAR 或单独的 UnRAR.dll。ZIP 继续使用已有的 ZIP 结构解析及核心 DLL 的解压服务；本次未增加 7z／TAR 或压缩包写入。

原版 5.7.9 的 RAR 后端在 EXE 中：`004738B5` 选择归档工厂，`00473338` 打开 RAR，`00474051` 按成员顺序生成 `archive.rar|member`，实际打开声音源时读取成员。本实现保留这个宿主模型，用新版引擎补上 RAR5。原版 67 个导出及其序号未变，新增接口不会让原版 EXE 自动取得 RAR5 支持，使用新接口的重建播放器才会调用它。

## 引擎、构建和兼容性

- 上游：[RARLAB UnRAR](https://www.rarlab.com/rar_add.htm)，固定 `7.3.1`。
- 源码：`https://www.rarlab.com/rar/unrarsrc-7.3.1.tar.gz`。
- SHA256：`634900842a3737d9cc15bbcc71d4c74cc713437e0bca296a573424fe5f2660ab`。

## ABI 1

头文件：`sdk/include/ttpcomm/archive_api.h`。新增具名导出 `ttpcomm_query_archive`，序号 **502**。连同 500、501，共 67 个旧导出和 3 个扩展导出。

调用方先初始化 `TtpCommArchiveApi.size`，查询 ABI 1，再验证 RAR4／RAR5 能力位及两个函数指针。SDK 的 `QueryArchive` 封装了此检查。结构采用固定宽度整数、UTF-16 字符串、回调和 `IStream`；不跨 DLL 边界传递 STL 对象或 CRT 释放责任。

| 接口 | 约定 |
| --- | --- |
| `enumerate` | 读取成员头，按归档顺序回调；不为普通成员解压内容，不按文件名排序 |
| `open_member` | 解压指定成员并完成长度、CRC／哈希验证；只有全部成功才返回只读 `IStream` |
| 成员属性 | Unicode 名称、64 位大小、字典大小、目录／加密／固实／链接／分卷标志 |
| `IStream` | 支持 Read、Seek、Stat、Clone、CopyTo；克隆共享只读存储并各自保存位置 |
| 密码 | 可由 options 提供 UTF-16 密码；引擎不保存密码 |
| 进度及取消 | options 回调返回 FALSE 取消；等待引擎锁、枚举、解压和固实前序处理均检查取消 |

枚举名称只在回调期间有效；需要保留时由调用方复制。所有返回流必须在卸载 DLL 前 Release。回调不得重入归档接口。上游含进程级错误状态，因此引擎调用串行化；已打开的成员流可以独立读取。

## 存储和限制

| 项目 | 默认策略 |
| --- | --- |
| 内存成员缓冲 | 16 MiB；调用方可设置，硬上限 64 MiB |
| 较大成员 | 使用 GUID 命名的独占临时文件，`FILE_FLAG_DELETE_ON_CLOSE`；不使用成员名作为落盘路径 |
| 单个成员 | 8 GiB，读取前检查大小，回调时禁止超出声明长度；CUE／文本缓冲适配器单独限制 64 MiB |
| 字典 | 默认 256 MiB，最高 512 MiB；固实前序成员也检查 |
| 成员数量 | 默认最多 100000 |
| 路径／链接 | 拒绝根路径、盘符、点及父目录片段；目录、链接不作为可播放成员 |

较大成员仍需先完整解压、校验，再交给解码器；磁盘空间不足会失败。固实归档读取后部成员可能需要重新解压前部数据，本次未实现跨歌曲固实缓存或并行预取。

错误区分缺少密码、密码错误、缺少分卷、字典超限、不支持的成员、CRC／数据错误、成员过大、取消及内存不足。分卷会读取同目录中可自动找到的后续卷；缺卷立即返回错误，不等待交互式选择。解压失败不暴露部分成员流。

## 播放器接入与发布

播放器的 RAR 枚举、声音源、Media Foundation、旧 Windows Media Reader、独立文件信息工作进程和包内 CUE 均使用此服务。音频 Reader 直接取得可定位的流，避免先完整复制至 vector，再复制至 HGLOBAL。

播放器启动及 Actions 的核心组件检查要求 502 归档接口，打包也校验 `archive_api_export`。发布顺序为：先发布含新接口的 `ttpcomm`，再构建／发布播放器。旧版已发布 DLL 不满足新播放器要求；更新时按既定方式手动替换完整包。

播放器目前未增加密码输入界面或归档专用进度对话框；没有提供密码时明确报告需要密码。取消／进度是可供宿主调用的引擎能力，尚未接入全部 UI 操作的取消按钮。普通 RAR 枚举仍在现有导入调用线程执行，包内 CUE 读取较慢时仍可能等待。
