# ttpcomm 重建实施记录

更新日期：2026-10-08。项目目录：`ttpcomm`。本记录区分“已实现并完成所列测试”和“完整替代原版”。

## 1. 当前结论

已建立独立 CMake x86 项目，实现原版 **全部 67 个有效导出**。
核心 DLL 可以独立运行，不加载旧 `ttpcomm.dll`，也没有导出转发器。
原版 DLL 仅在私有差分测试进程内作为参照同时加载。

当前输出 `build/Release/ttpcomm.dll`，接口版本仍为 `0x00050700`。
已在 XP、Win7、Windows 11 的隔离目录中实际替换测试副本的 DLL，验证两种播放器的加载、MP3 播放和退出。
“全部”指 67 个导出均有独立实现，不表示任意输入或任意宿主路径逐位相同。
已生成独立运行包和源码包，并接入可选的播放器发行组件。根目录参考 DLL 未改动，尚未执行远程发布。

## 2. 参考与 ABI

参考文件为上级目录原版 `ttpcomm.dll`：

- PE32 / x86，映像基址 `60000000`，文件 206,848 字节。
- SHA256：`e349ef73e8a1d35b2c5debd2ddaeb5cc2513a90647766b7339d2605b34483b33`。
- 67 个有效导出、66 个独立地址；序号 12 和 78 指向同一释放实现。
- 5 个具名导出，其余按序号导出；保留导出表中的空洞。
- 接口版本返回 `00050700`；Windows 文件版本采用日期构建规则。

证据来源为 `reverse/decompiled/ttpcomm.dll.pseudo.c`、原版 PE 数据/反汇编、原版宿主及插件调用点。
伪代码中缺失参数、寄存器变量和错误返回类型以二进制复核，不直接照抄伪 C。

`abi/exports.json` 保存全部序号、名字、原版地址、调用约定和恢复状态。
`cmake/check_abi.py` 检查实际导出集合、NONAME、12/78 别名及无转发器。
构建现在强制使用 `--require-complete`，缺失导出、错误命名、转发导出或破坏 12/78 别名都会失败。

### 3.1 运行时与所有权

RNG 保留 48 位递推、每线程状态、默认状态 `FFFF1111330E`、显式种子状态
`(seed << 16) | 330E`，以及 `srand48` 同时调用系统 CRT `srand` 的副作用。
使用两个动态 TLS 槽直接保存 48 位状态，高位槽加 1 区分默认值与全零状态。无需每线程堆分配，避免 DLL 卸载时其他存活线程的状态泄漏；兼容 XP 后续加载。

分配/释放通过 VC-LTL 对接系统 MSVCRT，避免将一个运行库分配的指针交给另一运行库释放。
测试实际覆盖导出 77 分配后由 MSVCRT 释放、MSVCRT 分配后由导出 78 释放。
虚对象仍由自身虚表的删除析构函数销毁。

安全处理器设置导出现已接到实际 MSVC /GS 失败报告器。根据 `60010CBD` / `60010D62` 汇编传入 `(1, nullptr)`；回调返回或抛出 SEH 后都终止，退出码为 3。独立子进程通过实际 `__security_check_cookie` 的失败分支验证，未通过破坏真实栈内存触发。无回调/重入时保留现代 fail-fast，旧系统直接终止；不恢复原版默认错误弹窗，也不执行受损进程的 DLL 清理。
栈恢复导出调用 CRT `_resetstkoflw`；未故意触发栈溢出作为测试。

### 3.2 ID3

不能直接把新版 libid3tag 的默认行为当作原版。当前在构建目录副本内做严格匹配修改：

- 新建标签版本 `0300`、选项 `10h`。
- 使用对象中的版本字段选择帧长度/扩展头/CRC 序列化规则。
- 保留原版不对写出帧实际压缩的行为。
- 导出 53 只解析 ID3v2；ID3v1 查询长度与解析行为分别对照。
- 后续帧错误时保留已成功解析的帧。
- 保留原版 v2.4 帧长度按普通大端整数读取的历史行为。
- Latin-1/UCS-4 转换保持字节映射；是否将旧 GBK 数据按系统代码页解释仍是宿主标签层的职责。

上游源码固定为 Tenacity libid3tag 0.16.4 并核验 SHA256。适配脚本检查预期片段出现次数，源版本变化时直接停止，避免静默应用错补丁。
已覆盖 UTF-16/UTF-8/Latin-1、文本/注释/图片/二进制/未知帧构造及两个实际 MP3 标签；新增 15,484 个保护页/变异/压缩帧用例，其中含 3,323 次分配失败注入；这仍不等于穷尽全部损坏输入。

### 3.3 解压

内部使用 zlib 1.3.2，导出层保留旧初始化限制：版本首字符、56 字节结构、正负 8–15 窗口位。
不因为后端升级就开放旧接口没有接受的 gzip/自动探测模式。

直接套用新版 `uncompress` 时，126 个容量/截断组合中有 87 个返回值或长度行为不同。
现按旧版“一次 `inflate(Z_FINISH)`”流程处理，失败时保留调用者目标长度，已消除这组差异。
已补充 837 组 raw/zlib/字典/分块/flush 输出对照、155 次自定义分配器失败和 12,000 个保护页变异流。54 组原版 raw Deflate 用例输出完整后仍等待预读字节，返回 Z_OK/Z_BUF_ERROR；新版返回 Z_STREAM_END。保留现代完整结束判断并明确记录该差异，未声称所有错误字符串和损坏流状态逐条相同。

### 3.4 ReplayGain

恢复 20 组采样率的二级滤波器及原版系数，不用其他分析器替换算法。
保留 50 ms 窗口、12,000 桶统计、百分位选择、曲目统计向专辑累计的时机和 6 声道混音顺序。
原版 peak 仅跟踪左侧/下混后的左侧，本模块保留该结果；不能把它当作全声道真峰值。

### 3.5 均衡器

恢复 10 段及前置增益、511 点 FIR、1024 点 FFT 卷积、每声道队列和首次丢弃 255 帧。
频段边界为 32/64/125/250/500/1000/2000/4000/8000 Hz，处理最多 10 个声道。
提交/取出数量以交错 double 样本数计；第 3 槽仍返回原版的 0，并不报告实际初始等待量。

特别保留两个经过汇编验证的细节：

1. `60006ECB` 把 `beta / I0(beta)` 放进外层 I0 的参数，不能直接改用标准 Kaiser 窗。
2. `600068E0` 清除待处理数、输出队列和首块标志，但不清除卷积重叠缓冲区。

新实现使用独立 double FFT，所列测试最大样本绝对误差约 `1.37e-13`。
这属于测得数值等价，不是逐位等同原版 Ooura FFT 的声明。
未把原版外层多声道空指针输入的危险行为恢复成可调用的排空功能。
已核对原版宿主 `004B1B81` 仅处理有数据的 PCM 块；EOF 的 `004B1BF4` 操作 `+3Ch` 重采样器，并非 `+40h` 均衡器。
36 组最终分块、队列取尽及下一曲 reset 对照通过，PCM 最大绝对误差 `1.44e-14`。
保留原版末尾不足 511 帧时不自动补零的规则。现已在两个播放器的隔离副本中捕获提交给 WaveOut 的 PCM：Win11 上 8 对场景、XP/Win7 各 2 对场景的新旧 DLL 输出逐字节相同。记录的是软件提交数据，不是声卡硬件或物理回环测量；范围详见第 7 节。

### 3.6 环绕、DTS、频谱

环绕保留量化的 200 Hz / 7000 Hz 系数、16 ms 延迟（上限 1024）、强度夹取、
前两声道加减及原版带符号右移的系数缩放；重置和多声道保留部分均已对照。

DTS 支持大/小端、16 位/14 位打包，通过相邻两个一致帧确认，填入原版 WAVEFORMATEX。
采用有界位读取；正常对齐输入结果一致。未对齐的小端输入，原版会受 32 位取数对齐影响拒绝，
新实现可以正常识别，这是有意修正，不列入“原版逐输入结果一致”。

频谱保留 1536 个 short 的工作区协议。
双声道的第二次变换从字节 `+400h` 开始，且发生在第一次结果写入之后；不能改成通常的简单左右声道分离。
此前 256 组中 5 个整数值相差 1，原因在 FFT 中间值精度，并非最终整数转换。
现对 KISS FFT 131.2.0 的前向 256 点复数 / 512 点实数分支恢复 `6000F790` 蝶形与 `600104B0` 实数解包中的单精度写回位置。
显式保留所需 double 中间值和 float 写回，没有引入整体 fast-math。
扩大到 **16,384 组**，XP、Win7、Win11 上输出及未修改工作区均逐值相同，测试不再允许差 1。
这是所列测试集的结论，不是所有浮点环境和所有可能输入的形式证明。

### 3.7 身份接口

保留首个网卡、原版 MAC 判定、至少 25 字节容量要求、12 位大写十六进制格式。
磁盘按原版 NT 路径顺序尝试 SMART、SCSI、Storage 查询；保留序列号筛选、大小写、截断规则。
组合接口保留 `uid=`、标志默认值、失败清位、`&mac=` / `&hds=` 拼接规则。

修正组合接口只校验值长度却漏算 5 字节分隔符的溢出风险，并对驱动返回长度/偏移做边界校验。
文件句柄使用确定释放，修正原版早退路径的泄漏。
测试全部使用注入的模拟网卡/磁盘数据，不读取或记录本机硬件标识。
XP 以前的 Win9x SMART 路径不在当前目标范围；真实不同控制器/驱动的兼容性仍未验证。

### 3.8 两套重采样

导出 102 的模式 1、2 创建 SSRC，其余模式创建多相 FIR；虚表顺序为析构、初始化、处理、reset。
两种算法的处理数量和输出容量都以交错 double 样本数计，不是字节数。

多相 FIR 独立恢复 35/40/45 阶选择、降采样加长、Kaiser 参数 16、相位推进和历史缓冲。
原版对过短输入块不会推进历史计数，此行为也保留；其 reset 是空操作。
SSRC 使用固定的历史上游，再恢复原版 double 路径、单精度 π 常量提升到 double、快速/高质量参数、
初始延迟、EOF 的 `floor(totalInput * outputRate / inputRate) + 2` 裁剪以及结束时的历史推进。
SSRC reset 实际执行 Finish 后清空输出队列，不会重新创建滤波器。

原版下采样构造 `6000E460` 分配 `n2x+n1b2+1` 个历史样本，却只清零前 `n2x+n1b2` 个，
末项会参与之后的叠加。实测其值会随之前的堆内容变化，不能作为确定的 PCM 基准。
新实现完整清零；私有对照仅把原版这一项清零后比较，未修改磁盘上的参考 DLL。
因此 SSRC 下采样结果属于明确初始化条件下的对照，不是对原版未定义内存行为的逐值承诺。

新实现还增加输出容量、声道数量和中间采样率乘法溢出保护。多相 FIR 在目标缓冲不足时返回 0，
不沿用原版忽略容量参数的行为；SSRC 会保留暂未取出的输出以供后续调用读取。

### 3.9 MPEG Layer I/II/III

使用 LAME 3.100 中的 mpglib 解码原语，改为全 double，恢复原版整数合成窗数据及归一化比例；
宿主接口由 `mpeg.cpp` 独立实现，没有使用 LAME 自动缓存输入、Xing 跳过或 gapless 裁剪接口。

- 原版消耗多少输入就在 I/O 中报告多少；未消耗的部分由宿主保留。
- 普通模式初始同步会检查下一帧，要求帧后至少还有 8 字节；短输入返回 1。
- 输出空间容纳不下完整帧时保留该帧；产生 PCM 时返回 0；错误返回 -1。
- 模式非 0 时按 ADU 分包处理，解码当前包内已经前置的主数据，不再重复拼接跨帧 reservoir。
- reset 清除头解析状态、位偏移及主数据历史，并恢复合成相位，但保留原版未清除的混合/合成缓冲。
- 对象全部内联分配，无外部后端句柄，可以继续交给导出 12 或系统 MSVCRT `free` 释放。
- `600121B0` 的 LSF 短块始终在 18 个 Huffman 对处切换区域，包含 8 kHz 和混合块；
  新版 mpglib 的规则不同，直接使用会产生可测 PCM 差异，现已恢复原版规则。

安全修正：拒绝超过 2880 字节的单个 ADU 包、非法块类型，以及声明主数据位数超过实际提供字节的包。
原版在部分截断包上仍会产生 PCM，读取路径没有相应的包内边界校验；此行为不予复现。
840 组错误/容量测试分别检查正常契约一致性及这些有意改变的拒绝行为，不能概括为所有损坏输入返回值都相同。
测试覆盖公开构造/处理/reset 接口，未承诺通过直接写原版私有对象偏移启用的 free-format 比特率等非公开用法。

### 3.10 Dream 视觉效果

固定使用官方 `wgoom-1.9.3-src.zip`，在构建目录恢复 TTPlayer 的对象、随机表、滤镜、IFS 和线条实现。
接口为 fastcall：创建、调整尺寸、传入左右各 512 个 short 样本并取回 32 位像素指针、销毁。
保留像素缓冲交替、自动/指定效果、平滑切换、音量扩张和原版逐帧状态推进。

从汇编和像素差分确认并恢复的细节包括：

- 0x4000 项 short 随机表和索引回绕；部分重复随机表达式取同一项而将索引推进两次。
- IFS 定点变换使用带符号右移，不能改成向零截断的有符号除法。
- 原版 double 三角函数及 x87 中间单精度舍入位置、单精度倒数常量。
- 音量扩张系数为 `0.0002f`，与下载上游不同；初始圆半径先做整数除法。
- 缩放插值恢复四个字节的加权、饱和和右移，使用标量实现，不遗留 MMX 状态。
- 原版正弦表实际只有 65535 项，索引 65535 会读到相邻速度字段；新实现以显式分支返回速度值，避免越界读取。

原版随机表只初始化前 16383 项，最后一项依赖堆内容。新实现将末项固定为 0；
私有差分仅将参考 DLL 运行内存中的这一项置 0 后比较，没有修改参考文件。
下述像素相同是此明确初始化条件下的结论，不包含未初始化内存的随机影响。

内存保护：校验尺寸与像素数、处理分配失败、释放上游遗漏的 IFS 缓冲区，
串行保护共享效果状态；每次处理恢复实例尺寸，避免不同尺寸实例互相污染。
这些是有意修正，不承诺复现原版错误参数导致的越界或崩溃。

### 3.11 CoolSB 与系统 API 拦截

以固定提交的 CoolSB 1.2 源码为基础，恢复 TTPlayer 的 `SCROLLBAR=0x350`、
`SCROLLWND=0x6C8` 布局和 `CoolSBSubclassPtr` 窗口属性；保持 ANSI 子类过程。
禁用原版未包含的附加按钮和工具提示路径，保留非客户区绘制、皮肤自绘通知、
命中测试、滑块拖动、箭头、捕获、悬停和平面样式，以及窗口销毁时恢复原窗口过程。

- 204 设置最小滑块长度及比例缩放；`SB_BOTH` 更新两个最小值，但比例标志仅赋给最后的垂直条，保留原版可观察行为。
- 205 设置箭头长度/宽度，保留 `-8..256` 且非零的取值限制。

- `SetScrollRange` 实际通过 `SetScrollInfo(SIF_RANGE)` 更新，返回当前位置；不能沿用上游返回 TRUE 的实现。
- 200/201 在当前进程安装/卸载 EnableScrollBar、GetScrollInfo、GetScrollPos、GetScrollRange、SetScrollInfo、SetScrollPos、SetScrollRange、ShowScrollBar。
- 未初始化 CoolSB 的窗口及独立 `SB_CTL` 控件回到真实 USER32 API；不影响其他进程。

拦截采用固定 Microsoft Detours 4.0.1，整组事务失败时回滚，重复初始化/退出保持幂等。
先收集线程和准备跳板，再暂停其他线程并修正指令位置；事务记账使用 VirtualAlloc，
避免被暂停线程持有 CRT 堆锁时造成死锁。卸载 DLL 前仍须先销毁其子类化窗口并调用 201。
新实现检查无效 HWND、分配和属性/子类安装失败；204 无效 bar 返回 FALSE，不复现原版的非法写入。
